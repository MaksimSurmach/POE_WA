## Implemented corrections

- Existing batched source rechecks durable settings, cancellation and source denial **after** each permit and before the request. Local pause/disable also cancels an active wait. Auth, access denied and an explicitly signaled challenge have different error codes; no retries follow them. Shared limiter state survives new pools/controllers; collection history supplies a durable source-wide denial latch, including when a late successful response changes the limiter's last HTTP status.
- Search metadata and each completed detail page are checkpointed to the running record before the next page. Interrupted-run recovery retains these raw rows without pretending they are a complete snapshot. A cancellation racing access denial retains the denial code and its durable blocker.
- Search evidence retains returned IDs, query ID, reported total, optional actual serialized request/raw response, and inexact. Actual request semantics enter the digest when provided. Inexact never establishes complete coverage. Existing transports without such evidence remain test seams, not authorized live implementations.
- Terminal collection runs publish through the existing immutable research snapshot writer. Snapshot and link commit together; a publication savepoint failure retains the terminal raw run and an explicit failure with no dangling snapshot link. Repeated terminal writes are idempotent; cache hits do not create snapshots. Profile digest/league/patch are checked again before publication.
- Collector snapshots reach the existing matcher/ranking API. Partial prices remain usable, with a preliminary warning. Collection-panel polling reloads the workbench/ranking when a new published snapshot appears.
- SQL history projection preserves `price:null`. Complete observations can establish absence after a positive partial observation or a repeated return; partial/inexact/cache responses cannot establish disappearance. Disappearance is never a confirmed sale.
- “Replication” here is coordination of processes against one PostgreSQL using the existing limiter, schedules and unique active-run constraint. No database HA topology or new cluster was added. No schema change was necessary: optional evidence lives in existing JSON payloads and historical rows remain readable.
