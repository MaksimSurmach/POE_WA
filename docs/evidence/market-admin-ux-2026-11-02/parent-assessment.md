# Independent layout/type assessment

Scope: e4fe03d, Market administration only. Mode Operate. Primary path: understand
market freshness/admission, request the required refresh, follow its outcome.
Settings/transport diagnostics are supporting work. No replacing Worksmith identity.
This assessment was written before reading the new Claude direction.

- Reading order: title/Pause -> six-cell status -> configuration warning -> Run and
  full run-history records -> settings. Run at y839 desktop, y1026 at390, y1170
  at320. The status and evergreen warnings still delay the primary task.
- Grouping: core operations and history are related, but the history has two full
  metadata paragraphs plus an error and details summary per record. Successful
  history and skipped records get almost as much weight as the current action.
- Rhythm: 20px repeated grids/panels, 22px padding and 14px paragraph margins make
  supporting prose feel like separate primary sections. Primary form fields do
  not align with Run, which occupies a standalone row.
- Structure/density: no stretched panels remain, but four large bordered regions
  plus always-present diagnostic disclosures and a disabled Save row consume
  space. Duplicate active-run/worker data can move to diagnostics. Retain healthy
  status truth, all errors, and every runtime control; hide detail, not capability.
- Adaptation: no overflow at1440/768/390/320. At768 the Run/History stack even though
  each could be a shorter region. At320 full metadata/prose creates height2608.
  DOM order is sound. Keep44px controls/focus; no CSS visual reordering.
- Extremes: API returns50 runs, all currently expanded. Use compact default history
  and disclose older records; active work must stay visible even if it is older.
  Recipe scope requires remembering/copying an ID. Use existing catalog titles.
- Authority/type: inherited Inter/system family is established; no new asset needed.
  Body16px, but metadata12.48px and mobile timestamp11.52px. Field labels13.6px,
  run headings14.4px. Too many near-small roles, despite clear weight hierarchy.
- Reading: prose line-height1.5; reasonable measure inside panels, but long runtime
  and warning sentences pull attention away from actions. Cut redundant narration;
  keep safety explanations once and next-action failures beside their controls.
- Stress/delivery: fixed roles should remain readable at320 and200% zoom, long
  recipe IDs must wrap inside details, no horizontal table scrolling. No new fonts,
  charts, modals, navigation, APIs or scheduling semantics.
